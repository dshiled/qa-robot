Three things, done properly

Not a browser cloud. A control point for automated testing in environments that cannot send their data to a third party.

🛡

Generated tests get scanned

Prompts and generated code are checked for credential theft, data exfiltration, prompt injection and production side effects before anything runs. Blocked tests are recorded, not silently dropped.

🗂

An audit trail, not a log file

Append-only event log with actor, tenant, IP and user agent for every run, block and key event. Export as JSON when your auditor asks what your automation did last quarter.

🏠

Runs where your data already is

One Node process and a SQLite file. Keys, jobs and history live on your hardware — useful when the vendor contract says the test suite cannot leave the building.

Security posture, stated plainly

What this software does and does not do. Read this before you evaluate it.

Every API route requires a key

All 24 endpoints authenticate with a bearer token. Keys are stored in SQLite, rate limited, and revocable.

No shell interpolation

Test names are allowlisted and executed as an argument array, never concatenated into a command string.

Same-origin by default

No CORS headers unless you configure an explicit allowlist. Keys are refused from query strings.

SSO is not enabled

SAML is switched off rather than shipped unverified. The dashboard uses API keys only. A known gap, not an oversight.

No compliance certification

QA-Robot produces evidence. It does not make you HIPAA or SOC 2 compliant, and we do not claim it does.

No telemetry

SQLite on your disk. No analytics endpoint, and no outbound connection except to the AI provider you configure.
